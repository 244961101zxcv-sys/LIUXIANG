01

MENTAL MODEL

先理解：GitHub Pages 是什么

GitHub 是一个存放代码和文件的网站。一个 repository（仓库）就是一个项目文件夹；GitHub Pages 是它附带的静态网站托管服务。你把这个文件夹里的 index.html、CSS、JS、图片和模型放进去，GitHub 就会用它们生成一个公开网址。

A

仓库 = 文件夹

本地文件夹里的目录结构，上传到仓库后要保持一致。线上路径区分大小写。

B

提交 = 保存版本

每次修改后提交一次（commit），Pages 会自动重新构建网站，通常 1–3 分钟。

C

没有后端

网站不能把访客上传的文件写回 GitHub。策展台上传只存在你的浏览器里，发布要导出更新包。

先明确“上传”的两层含义。在网站的策展台里上传模型，只保存在当前浏览器，方便你预览和调整；要让所有访客看到，需要把模型文件放进 GitHub 仓库。这是静态网站的正常工作方式，不是 bug。

免费账号使用公开仓库即可。GitHub Pages 的常见限制：单个文件小于 100MB，仓库建议控制在 1GB 以内，每月流量约 100GB，构建约 10 分钟超时。对 10 个压缩后的 GLB 模型来说，空间通常够用。

官方文档：GitHub Pages · Pages limits · Large files

02

FILES

准备网站文件夹

拿到 作品集网站 文件夹后，先确认 index.html 在最外层，而不是在某个子文件夹里。仓库的根目录必须能直接看到它。

作品集网站/
├── index.html          ← 首页，必须在根目录
├── guide.html          ← 你现在看的这份指南
├── 本地预览.bat         ← 本地打开网站
├── data/
│   └── works.json      ← 10 个展示位的数据
├── models/             ← 发布后的 3D 模型放这里
├── assets/
│   └── covers/         ← 作品封面
├── css/
├── js/
└── vendor/             ← Three.js、JSZip 等依赖

不要修改 vendor/。它存放 Three.js 和 JSZip，是网站的渲染与打包依赖。你只需要改 data/works.json、models/、assets/covers/，以及首页里的姓名和联系方式。

建议先改三处个人信息

  1. 打开 data/works.json，把 meta.artist 改成你的名字，meta.email 改成邮箱。
  2. 需要 ArtStation 的话，把 meta.artstation 填上主页地址；不填就留空。
  3. 如果作品标题、方向或说明要改，也在同一个文件里改；每个对象对应一个展示位。

03

FIRST DEPLOY

创建仓库并发布

  1. 注册 / 登录 GitHub

    打开 github.com。记住你的用户名，它会出现在最终网址里。

  2. 新建一个公开仓库

    右上角 + → New repository。Repository name 填 form10（或你喜欢的名字），选择 Public。不要勾选 “Add a README file”，保持空仓库，下一步一次上传完整网站。

  3. 把网站文件上传到仓库根目录

    进入仓库 → Add file → Upload files。把 作品集网站 文件夹里面的内容全选拖进去（不是把外层文件夹本身拖进去）。确认页面上能直接看到 index.html，然后点 Commit changes。

    如果拖folder后页面显示 作品集网站/index.html，说明多套了一层，删掉重传或把文件移动到根目录。

  4. 开启 Pages

    仓库顶部 Settings → Pages。Source 选择 Deploy from a branch，Branch 选 main，目录选 / (root)，点 Save。

  5. 等待并打开网址

    回到 Pages 页面，等上方出现绿色提示。网址通常是：

    https://你的用户名.github.io/form10/

    如果仓库名正好是 你的用户名.github.io，网址就是 https://你的用户名.github.io/。第一次部署通常 1–3 分钟，偶尔更久。

404 先查三件事：仓库是不是 Public；Pages 的 Branch 是不是 main / root；index.html 是不是在根目录。改完设置后等一分钟再刷新。

04

MODEL WORKFLOW

上传模型，再发布到线上

推荐流程是“先本地预览，再导出更新包”。这样你能确认模型、灯光和封面都对了，再把文件推到 GitHub。

01

本地预览

双击 本地预览.bat，浏览器打开 http://127.0.0.1:8080/。不要直接双击 index.html，ES Modules 会被浏览器的本地文件安全策略拦住。

02

策展台上传

点右上角“策展台”，选择第 8–10 个空缺展示位（或替换已有作品），把 GLB 拖进去。填写作品名、类型和一句话说明，保存。

03

检查 3D 预览

用鼠标中键旋转、左键平移、滚轮缩放。手机上一根手指旋转、两根手指捏合缩放。角度满意后点“截取封面”。

04

导出发布包

回到策展台，点“导出发布包”。ZIP 里有 models/、covers/ 和更新后的 data/works.json。

把发布包放到 GitHub

  1. 解压 form10-site-update-日期.zip。
  2. 在仓库首页点 Add file → Upload files，把解压后的 models、covers、data 文件夹拖进去。
  3. 同名文件选择覆盖，Commit changes。
  4. 等 Pages 重新部署，用无痕窗口打开线上网址检查。

只上传 data/works.json 是不够的。模型文件和封面图也要在仓库里，否则线上访客只会看到空白或加载失败。三个目录要一起提交。

也可以手动改数据

如果只想发布一个模型，可以手动在 models/slot-08/ 放文件，然后在 data/works.json 对应展示位里把 model 写成相对路径：

{
  "slot": 8,
  "title": "银发剑士",
  "category": "character",
  "role": "3D 角色 / 二次元手绘",
  "cover": "assets/covers/08.webp",
  "model": "models/slot-08/character.glb",
  "description": "一句话说明这件作品。",
  "specs": ["角色 + 武器", "2K 贴图"]
}

路径相对网站根目录，不要以 / 或盘符开头；线上区分大小写，Model.glb 和 model.glb 是两个文件。

05

BLENDER → GLB

Blender 导出设置

网站推荐单文件 GLB：模型、材质和贴图都打包在一个文件里，上传和排错都最简单。Blender 的路径是 File → Export → glTF 2.0 (.glb/.gltf)。

格式glTF Binary (.glb)
包含Selected Objects（只导出选中的角色/道具）
变换+Y Up，Apply Modifiers
数据UV、Normals；需要时再勾 Tangents
材质Export Materials / Images: Automatic
相机 / 灯光不要导出
压缩可选 Draco；网站已支持
建议大小单个 ≤ 20MB，硬上限 100MB

导出前的模型检查

  • 在物体模式执行 Object → Apply → All Transforms，避免缩放和旋转留在模型上。
  • 把原点放到脚底中心（角色）或物体中心（道具），这样旋转和落地更自然。
  • 确认场景里没有多余的相机、灯光、参考板和隐藏物体被一起导出。
  • 贴图尽量统一为 2K；4K 贴图会显著增加 GLB 体积和手机加载时间。
  • 超过 10 万三角面的角色建议先做游戏级低模；网页不是离线渲染器。
  • 导出后在 glTF Viewer 里再打开一次，确认没有丢失材质。

如果模型带多个贴图文件，网站也支持把 .gltf + .bin + textures 整个文件夹拖进策展台；但发布时这些文件必须保持相对路径一起上传。新手优先用 GLB。

Blender 官方手册：glTF 2.0

07

ITERATE

之后怎么更新

发布不是一次性的。之后每次改作品、换封面或加新模型，都是同一个循环：改文件 → 提交 → 等 Pages 重新部署。

只用浏览器

在仓库里点文件 → 右上角铅笔编辑 → Commit。新增模型用 Add file → Upload files。适合偶尔改一两处。

用 GitHub Desktop

把仓库 Clone 到电脑，在本地文件夹里替换模型和 works.json，写 Commit message，点 Push。适合经常更新。

更新时的三个习惯

  • 提交信息写清楚，例如 Add slot 08 character model，以后能找回版本。
  • 不要提交 .blend 源文件、PSD、未压缩贴图；仓库只放网页要用的 GLB 和 WebP/JPG。
  • 每次发布后用无痕窗口打开线上网址，确认访客看到的是新版本，而不是浏览器缓存。

不要用 Git LFS 存 GLB。GitHub Pages 不会把 LFS 指针解析成模型文件。直接把压缩后的真实文件提交到普通 Git 仓库。

08

TROUBLESHOOT

常见问题

线上是 404 / 一片空白

先确认仓库是 Public、Pages 的 Branch 是 main / root、index.html 在根目录。按 F12 看 Console 和 Network：如果 js/app.js 或 data/works.json 404，通常是路径大小写或多套了一层文件夹。

模型一直停在 LOADING，或显示 LOAD ERROR

优先换成单文件 GLB；确认 data/works.json 里的 model 路径和仓库中的文件完全一致；确认文件小于 100MB。带外部贴图的 GLTF 必须把 .bin 和 textures 一起上传，并保持相对目录。

模型能打开，但材质是黑的 / 没有贴图

多数是 GLTF 的外部贴图路径断了，或导出时没有打包图片。回到 Blender 重新导出 GLB，Images 选择 Automatic，确认贴图节点使用的是图片文件而不是程序纹理。

手机上单指旋转不灵 / 页面跟着滚动

预览器的画布已经设置 touch-action: none。如果仍然冲突，确认你点的是模型画布而不是下方信息面板；页面本身在查看器打开时是锁定滚动的。

策展台上传成功，但别人看不到

这是正常的。策展台的文件存在浏览器的 IndexedDB 里，只对你当前这台设备可见。点“导出发布包”，把 models/、covers/、data/works.json 提交到 GitHub 后，访客才能看到。

更新后线上还是旧版本

打开仓库的 Actions 看 Pages 部署是否完成；用无痕窗口或强制刷新（Ctrl/Cmd + Shift + R）。GitHub CDN 可能有几分钟缓存。

可以换成自己的域名吗？

可以。Settings → Pages → Custom domain 填入域名，再按 GitHub 提示配置 DNS。个人作品集用 username.github.io 已经足够，先不必折腾域名。

09

BEFORE YOU SHIP

发布前检查

  • 01姓名、邮箱、ArtStation 已替换，没有 YOUR NAME 残留。
  • 027 个原有项目的封面和说明没有在替换模型时被覆盖。
  • 03每个 3D 模型都能在电脑和手机上打开，左键/中键/滚轮与单指/双指都正常。
  • 04每个展示位都有封面；新模型已用“截取封面”生成 4:5 缩略图。
  • 05线上 models/、covers/、data/works.json 三处都已提交。
  • 06用无痕窗口在手机尺寸下看过一遍，文字没有被裁切。
  • 07GLB 总体积可控，首页 3 秒内能出现内容。
  • 08没有把学校作业、未完成作品或他人模型标成个人原创。
